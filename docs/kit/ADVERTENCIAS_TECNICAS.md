# Leer antes de implementar

1. No se recibió el código del primer parcial. backend/ es una implementación alternativa, NO un parche probado de su sistema anterior. Si este ya funciona, conservarlo y adaptar contratos y analítica; no reemplazarlo a ciegas.
2. Se encontró un desacuerdo: enunciado y DATA.md dicen bookings=CONFIRMED; oracle.py usa d.groupby(...).size(), que incluye CANCELLED. El trabajo entregado sigue el enunciado. validate_parquet.py compara las demás métricas y verifica bookings=seats_sold, señalando la diferencia. Consultar al docente. No editar el oráculo ni el evaluador para ocultarla.
3. test_metrics_table_contract exige que las columnas del StorageDescriptor comiencen exactamente por METRIC_COLUMNS, que contiene month en segunda posición. Particionar métricas por month lo sacaría de esa lista. Por eso las métricas se escriben SIN particionar. El detalle sí se particiona; test_partition_pruning_scan consulta el detalle, no métricas. El enunciado menciona particiones de ambas de forma general; confirmar esta interpretación con el docente. Esta elección está permitida expresamente en DATA.md.
4. El top-10 correcto es SUM(seats_sold)/SUM(seats_capacity) agrupado por route sobre todos los meses. No es ORDER BY occupancy de filas route-month ni AVG(occupancy) simple.
5. Aunque se retiró la semilla del informe visual por petición del equipo, sigue siendo obligatoria para generar datos y config.yaml. Usar la asignada, nunca inventarla. El valor 12345 del ejemplo original no es una asignación.
6. El lector de reservas acepta un único CSV del generador, sin campos multilínea. zipWithIndex fija un ordinal sobre el flujo de líneas ANTES de filtrar, unir y redistribuir; se usa para conservar la primera reserva válida. No cambiarlo a dropDuplicates ni a monotonically_increasing_id sin justificar equivalencia.
7. El generador aproxima --rows; no produce necesariamente exactamente 2.000.000 filas. La referencia es el mismo generador con los mismos parámetros, no un corte manual del CSV.
8. El evaluador proyecta algunas instancias activas a 730 horas. Declarar solo unas horas de uso puede no coincidir con su estimación R12. pricing.yaml tiene precios ilustrativos NO actuales; no es una factura ni una cotización validada. Revisar contradicciones con el docente sin cambiar sus archivos.
9. El servidor usa biblioteca estándar y PostgreSQL mediante psycopg. Es una base académica legible, NO una plataforma endurecida para producción. No incluye usuarios, pagos, autenticación ni HTTPS. Limitar acceso y no publicar datos reales. SQLite es exclusivamente para pruebas locales; AWS usa PostgreSQL.
10. Timeout Athena de la aplicación no garantiza R7: las llamadas SDK y latencia de red pueden superar el plazo. Medir el extremo a extremo en el laboratorio; si no cumple, analizar registros y tamaño de consulta. No falsear respuestas ni sustituir Athena por datos precalculados en la API.
